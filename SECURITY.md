# Security Policy

## Supported version

Security fixes are prepared for the latest official release. Older builds may not receive patches.

## Reporting a vulnerability

After the GitHub repository is public, use **Security → Advisories → Report a vulnerability** for private reporting. Until that channel exists, do not publish exploit details; contact the founder through a private contact method that the founder explicitly publishes with the repository.

Include the affected version, impact, minimal reproduction, and suggested mitigation. Do not include real credentials, account records, or unnecessary personal data.

The project will acknowledge a usable report when a maintainer is available, assess severity, coordinate a fix, and credit the reporter if requested and safe. No guaranteed response time or bounty is promised.

## Scope

Relevant issues include extension permission abuse, unsafe storage, script injection, dependency compromise, malicious release artifacts, secret exposure, and workflows that grant excessive permissions. Formula disagreements and educational errors use the formula-correction issue form unless they create a security impact.

## Safe research

Do not access other people's accounts or data, degrade services, bypass browser security, or publicly disclose an unpatched vulnerability. This policy does not authorize testing against TradingView or any third-party service.
